1. THE TWO MACHINES (both are SINGLE-ANCHOR -- decode one contract each)
--------------------------------------------------------------------------------
MORPHO BLUE (isolated markets):
  - One singleton. Every market = (loanToken, collateralToken, oracle, irm, lltv).
  - COLLATERAL and LOAN are DIFFERENT tokens, tracked separately (isolated).
  - Events: Supply/Withdraw (lend loanToken), Borrow/Repay, SupplyCollateral/
    WithdrawCollateral, CreateMarket (id->tokens), Liquidate, AccrueInterest.
  - AccrueInterest emits updated totalSupplyAssets + totalBorrowAssets = STATE.

AAVE V4 HUB-AND-SPOKE (pooled):
  - One HubInstance holds shared liquidity per asset. Spokes (Main, Forex) add/
    draw. SUPPLIED assets DOUBLE AS COLLATERAL (pooled model, no separate
    collateral token like Morpho). assetId indexes each asset.
  - Events (VERIFIED field names from decoded ABI):
    AddAsset(assetId, underlying, decimals)          -> assetId->token map
    AddSpoke(assetId, spoke)
    Add(assetId, spoke, shares, amount)              -> SUPPLY (net = liquidity in)
    Remove(assetId, spoke, shares, amount)           -> withdraw
    Draw(assetId, spoke, drawnShares, drawnAmount)   -> BORROW
    Restore(assetId, spoke, drawnShares, ..., drawnAmount, premiumAmount) -> REPAY
    Reclaim(assetId, reinvestmentController, amount) -> fee/reinvestment, NOT a
      user repay. DO NOT count as repay.
    UpdateAsset(assetId, drawnIndex, drawnRate, accruedFees) -> borrow INDEX+RATE
      + fees. NOT total liquidity/debt. (Correction: earlier draft wrongly called
      this a supply/debt state snapshot -- it is not.)
    TransferShares, MintFeeShares, ReportDeficit/EliminateDeficit.
  - Hub confirmed BUSY: dozens of events/day as of 2026-09-28.

=> HOW THE TOTALS COME OUT (Aave is SHARE-based):
   - Supply = Add.amount - Remove.amount (net underlying).
   - Borrow = Draw.drawnAmount - Restore.drawnAmount (net underlying).
   - drawnIndex (latest UpdateAsset) converts debt shares -> exact current debt.
   V1 METHOD = net underlying flows. Valid NOW because market is ~2 weeks old ->
   accrued interest negligible. This is NOT the general-case fix (flow-netting
   broke on mature Morpho assets); the accrual-exact method = net shares x index,
   flagged as v2. Validate both vs app.aave.com. Morpho side: AccrueInterest DOES
   emit totalSupplyAssets+totalBorrowAssets (real state) -> use that for Morpho.

ARCHITECTURE CAVEAT for an HONEST comparison:
  - "Collateral" is NOT apples-to-apples. Morpho = explicit separate collateral
    token per isolated market (SupplyCollateral events). Aave = supplied assets
    are the collateral (pooled). Report Morpho collateral as its own line;
    for Aave, "collateral" = supplied balance backing a borrow. Label precisely.
  - Compare SUPPLY (real capital in) and BORROW (loans out) + UTILIZATION as the
    common ground. Collateral breakout = Morpho-specific extra tile.

--------------------------------------------------------------------------------
5. GUARDRAILS (banked lessons)
--------------------------------------------------------------------------------
- STATE over flow for TVL (latest UpdateAsset / AccrueInterest). Flow-netting only
  as fallback; it broke on high-churn assets (USDC/USDT) before.
- BOUND the prices.usd join to a recent window -- unbounded price join = the
  timeout that bit us on Arc Morpho.
- Aggregate BEFORE union; never union raw events. Materialize heavy scans; the
  dashboard reads small tables.
- Anchor/hub layer only. Morpho: count Blue, not vaults (double-count). Aave:
  count Hub, not spoke pass-throughs.
- LABEL precisely: supply != collateral != borrow != utilization. Note the
  Morpho(isolated) vs Aave(pooled) collateral difference every time (sec 1).
- Symbol collisions: 1000+ contracts print "USDC" on Arc. Pin by address. Exclude
  0xffff...fffe (USDC double-count alias) in any raw transfer work.
- VALIDATE vs app.morpho.org/arc and app.aave.com before shipping (ground truth).
