AAVE x COINBASE STOCKS — INCENTIVES TRACKER (live site, not Dune-hosted)
================================================================================
For: Vector. Purpose: a hosted site (Netlify) that combines Dune on-chain data +
Merkl live API into one sweet-looking incentives dashboard w/ write-ups. The
Base stock-lending reputation piece. Chain = BASE. Created: 2026-10-14.

--------------------------------------------------------------------------------
0. THE MENTAL MODEL (what sits where)
--------------------------------------------------------------------------------
Dune  = the SQL DATA ENGINE (stays). We keep writing queries there.
Merkl API = the LIVE EMISSION truth (daily $ distributed, APR, budget).
The SITE = the PRESENTATION layer that pulls from both + our write-ups. Netlify.
So we are NOT abandoning Dune -- Dune is the backend; the site is the frontend.

WHY HYBRID (not pure Dune): Aave pays these incentives through MERKL, which is
computed OFF-CHAIN and claimed ON-CHAIN. There is no on-chain "X emitted today"
event. On-chain you only see (a) campaign funded, (b) users CLAIM. So:
  - "daily distributed / APR / budget"  -> Merkl API (the schedule lives there).
  - "actually claimed on-chain / who / when / TVL moved" -> Dune (our verify layer).
The GAP between emitted (Merkl) and claimed (Dune) = incentive efficiency = story.

4. SITE ARCHITECTURE
--------------------------------------------------------------------------------
STACK: Vite + React + Recharts (or Next.js static). Host: Netlify. Vector knows
  Next/TS already -> low friction.
DATA WIRING (v1 -- simplest, free, ship fast):
  - Merkl: fetch LIVE client-side from api.merkl.xyz on page load (CORS fallback:
    small Netlify function proxy at /api/merkl).
  - Dune: EXPORT each query's results to /public/data/<name>.json, commit to repo.
    Refreshes when you redeploy. Good enough for a 9-day campaign.
DATA WIRING (v2 -- auto-refresh, optional upgrade):
  - Netlify SCHEDULED FUNCTION (hourly) -> calls Dune API (needs Dune API key,
    paid tier) + Merkl API -> writes combined JSON to Netlify Blobs or Supabase
    (Vector has Supabase) -> frontend reads that. Makes it feel truly live.
  - Keep the Dune API key in a Netlify env var / function, NEVER in the frontend.
RECOMMENDATION: ship v1 now (campaign is only ~9 days), add v2 only if it gets
  traction or becomes a recurring product.

--------------------------------------------------------------------------------
7. RISKS / GOTCHAS (banked)
--------------------------------------------------------------------------------
- Early days = near-ZERO on-chain claims (Merkl posts Merkle roots periodically;
  users claim later/in batches). Don't read empty Claimed events as a bug -- the
  Merkl API carries the story first; Dune catches up.
- Hub vs spoke duplication in Merkl opportunities -> don't double-count daily $.
- Reward-token filtering: if token is shared, Dune claims aren't Aave-isolated.
- Dune API live-fetch needs a paid tier; v1 uses static JSON to avoid that.
- Non-US geo gate on the market is unchanged by incentives (context for write-up).
