0. WHAT ETCHY ACTUALLY IS (from their own GitHub: EtchydotFun/etchy-zero)
--------------------------------------------------------------------------------
Etchy Zero = an AMM for REAL Bitcoin Runes, traded on SOLANA. Not a wrapped
token: the Rune itself stays in a Bitcoin Taproot vault, and Bitcoin events are
verified on Solana. So it's a cross-chain Runes<->Solana trading system.
  - Pools: each holds ONE Rune, trades it vs WBTC on a constant-product curve.
    Virtual BTC reserve sets ~0.035 BTC starting mcap. Pool opens only after the
    Rune's etching is proven; full premine must sit in the pool vault.
  - Balances: accounts in the rune_pool program (NOT SPL tokens), keyed by owner.
    Owner can be a Solana wallet OR a Bitcoin wallet (Taproot key, signed msgs).
  - btc_relay: a Bitcoin light client on Solana (takes BTC headers, follows most-
    work chain, checks PoW). rune_pool verifies Merkle proofs against it + applies
    ord Runestone rules -> learns etchings, vault deposits, payouts.
  - Vault: each pool's Runes sit at a Taproot address; key = threshold Schnorr key
    held by an Internet Computer (ICP) canister. If a proven tx leaves a vault
    SHORT, the program HALTS that pool. (<- critical event to watch.)
  - Swaps/pricing: uses Jupiter (swaps), NEAR Intents (BTC in/out), Pyth (prices).
  - "ETCHY*FUN" is itself a Rune traded in a pool (their flagship), not a minted token.
  - NO separate ERC20/SPL "ETCHY token" described in the code.

      UniSat: /v1/indexer/runes/{rune}/holders. (confirm exact paths in docs.)

  VAULT FLOWS (ETCHY per-pool Taproot vaults): rune balance AT a vault = Runes API;
